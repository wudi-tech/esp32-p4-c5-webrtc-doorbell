# LD2450 雷达安装和测试矩阵

日期: 2026-09-04  
固件分支: `feat/wt99p4c5-doorbell`  
P4 序列端口: `COM5`

## 任务 8 的固定线路

只能用电板和雷达供电。

| LD2450 针 | 连接 | 目的 |
| --- | --- | --- |
| `5V` | 5V供应 | 雷达功率; 模块供应必须提供200 mA以上。 |
| `GND` | 供应 GND 联合国 WT99P4C5-S1 J6 标点 11 (GND) | 雷达， 供应， 发展基础必须是共同的. J6 针头 13/15/17 等同为 GND 备选案文。 |
| `TX` | WT99P4C5-S1 J6 针头 10 / P4 GPIO4 | 雷达数据至 P4 UART1 RX。 |
| `RX` | WT99P4C5-S1 J6 针头 12 / P4 GPIO5 | P4 UART1 TX 到雷达配置输入. 可选择只接收任务 8.1, 但保留给后期配置。 |

不要连接雷达的5V针 GPIO. 那个 UART 信令是 3.3 V。
在第一次雷达试验中保持伺服器电源的断开，这样功率
或者噪音断层很容易分离。

## 议定书基准

- UART: 256 000 鲍尔， 8 个数据位， 无对等， 1 个停止位。
- 数据率: 每秒约10帧。
- 数据框架: 固定 30 字节， 标题 `AA FF 03 00`, 3个8字节目标
  记录， 尾声 `55 CC`, 无校验和。
- 零填充的8字节目标记录意味着目标位置是空的。
- X, Y, 并使用 LD2450 direction/magnitude 编码: 位 15 集为
  正数; 位 15 清晰为负; 位数 0-14 保持大小。

主机解析器测试包含在 LD2450 协议文档中。它必须将目标 1 解码为
X=-782 毫米、Y=1713 毫米、速度=-16 厘米/秒、距离分辨率=320 毫米。
接线完成后，将补充从实物雷达采集的实时数据帧。

## 第一个现场测试序列

1. 启动所有设备 完成上面四个连接。
2. 把服务器的电源断开。
3. 闪烁任务 8.1 软件 P4 通过 COM5。
4. 开始 COM5 显示器， 然后用5V为雷达提供动力。
5. 检查 UART-准备就绪并观察现场目标日志，同时待命,
   接近时， 移动侧面， 离开。
6. 在任务开始前记录代表性原始框架 8.2 区域并解除
   逻辑。

任务 8.2 在现场直播前不能开始 UART 上行通过. 解析器， UART
阅读器， 而后来的存在-聚变逻辑仍然是独立的层。

## 任务 8.3 有组织的雷达事件

雷达事件路径使用专用的边框遥测队列，而不共享
联合国 WebRTC 正在显示队列. 当遥测队列满满时， 最古老的雷达
事件被丢弃，以便信令和雷达 UART 呼叫从不
已封锁. 浏览器保存最新的100个条目并插入所有设备值
与 `textContent`。

| 测试 | 结果 | 证据/接受条件 |
| --- | --- | --- |
| Event-schema 主机测试 | 通过 | 准确 JSON 形状， enter/leave 名称， 无效的音轨标识， 和尺寸不足的缓冲器通过。 |
| 所需字段 | 通过 | 事件包含单调 `timestamp`, LD2450 基于槽 `track_id`, `x_mm`, `y_mm`, `speed`, `zone`, `confidence`, 联合国 `source`. LD2450 没有信心价值， 所以这是明确的 `null`。 |
| 信令隔离 | 通过 | 遥测使用单独的16进制固定大小队列; 一个完整队列在不阻断的情况下放下其最古老的遥测项目。 |
| 浏览器安全和列表绑定 | 通过 | 雷达事件与 `textContent`; 列表上限为100个最新条目。 |
| 现场直播 SSE 交付 | 通过 | 2026-09-06 (英语)。, 物理板位于 `192.168.0.103` 已交付 `connected`, 输入事件 (`track_id=1`, `x=225`, `y=308`), 休假活动， 和周期性心跳消息结束 `/webrtc/signal`。 |

实例直播事件：

```json
{"type":"radar_event","event":"enter","timestamp":30572,"track_id":1,"x_mm":225,"y_mm":308,"speed":0,"zone":"door_approach","confidence":null,"source":"ld2450"}
```
