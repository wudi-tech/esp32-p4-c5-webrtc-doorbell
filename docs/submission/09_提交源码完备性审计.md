## 六、上游源码与提交边界

提交快照共有约 476 个文件。除上述项目自有和适配文件外，其余主要来自 Espressif `esp-webrtc-solution` 基线及仓库内本地组件，例如 `esp_webrtc`、`esp_peer`、`av_render`、`codec_board` 和 `media_lib_utils`。这些上游文件由构建系统整体使用，不应为了“显得精简”随意删除，因此在审计中按组件整体保留，不逐个改写职责。

下列内容不应进入最终源码快照：

- `build/`、`build-audit/`、`managed_components/`；
- 本机生成的 `sdkconfig`、`sdkconfig.audit`；
- `settings.local.h` 和真实 Wi-Fi 凭据；
- `.git/`、编辑器缓存、PID、临时日志；
- 含本机绝对路径的自动生成 `dependencies.lock`。

不提交 `managed_components` 不代表缺少源码：ESP-IDF Component Manager 会按 `idf_component.yml` 解析外部依赖；本仓库覆盖的核心组件则已在 `components/` 中随包提供。

## 七、必须由实机视频证明的项目

以下项目不能被“编译通过”替代，提交视频中应至少各出现一次：

1. BOOT 按键触发网页来电，网页和板端铃声停止逻辑一致；
2. 网页接听后能看到板载摄像头视频并双向通话；
3. 通话中点击开门，舵机执行且能听到开门提示；
4. LD2450 事件中的横向 X、前向 Y、速度和进出状态与人的实际移动一致；当前版本没有雷达俯视轨迹，不应在视频中宣称已经实现；
5. 摄像头只做人员/人脸存在判断，不宣称身份识别；
6. 雷达与视觉均提供证据后触发一次来电，同一来访不连续累积来电；
7. 挂断后音视频真正停止，刷新网页后仍可再次来电；
8. 连续运行期间没有重启、看门狗、栈溢出或舵机持续堵转。
