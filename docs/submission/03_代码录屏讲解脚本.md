**我说：**

## 4.3 六条完整调用链

### 系统启动

```text
app_main
  → init_board
  → doorbell_webrtc_init
  → multimodal_fusion_init
  → door_lock_init
  → presence_fusion_init
  → radar_ld2450_init
  → media_sys_buildup
  → network_init

```

### BOOT 来电

```text
GPIO35 变化
  → key_monitor_thread
  → doorbell_request_ring("boot")
  → ring policy + 状态预留
  → SEND_CMD("RING") + 板端铃声
  → SSE
  → 浏览器来电 UI + 网页铃声
```

### 浏览器接听与视频出现

```text
接听按钮
  → sendCustomCommand("ACCEPT_CALL")
  → POST /webrtc/signal
  → door_bell_on_cmd
  → schedule_peer_connection_change(true)
  → SDP/ICE 交换
  → ESP_WEBRTC_EVENT_CONNECTED
  → 浏览器 ontrack
  → remoteVideo
```

### 通话中开门

```text
OPEN_DOOR
  ├─ door_lock_request_open → queue → door_lock_task → PWM 打开/复位
  └─ play_open_door_prompt_in_call
       → doorbell_audio_prompt_start
       → prompt_render_write
       → pcm_overlay_mix_mono
       → ES8311 扬声器
```

### 雷达与视觉自动来电

```text
LD2450 UART → parse → presence_fusion ──────────┐
                                                ├─ multimodal_fusion
OV5647 → ESP-DL → vision_tracker → vision event ┘
  → request_sensor_ring("radar+vision")
  → doorbell_request_ring
```

### 确认式挂断

```text
挂断按钮
  → DENY_CALL
  → 板端 disable PeerConnection
  → CALL_ENDED
  → finalizeHangup
  → 关闭 PC、停止本地麦克风、清空远端视频
```

## 六、容易讲错的内容

- 不能说“人脸识别”：当前仅做人脸存在检测，不保存身份特征。
- 不能说“86% 准确率”：它是单个候选框的模型置信分数。
- 不能说“雷达点云”：LD2450 输出最多三个二维目标点。
- 不能说“已完成雷达俯视图”：当前只有坐标、速度和中文事件，俯视轨迹是未来扩展。
- 不能把事件数量说成实时人数：它是有限历史记录。
- 不能说“已经安装真实门锁”：当前是空载 180° 模拟舵机。
- 不能说“屏幕已经启用”：屏幕只保留板级支持和未来扩展位置。
- 不能说“网页使用 WebSocket”：下行是 SSE，上行是 HTTP POST，媒体才是 WebRTC。
- RTP Transformer 是编码 RTP 包的调试变换示例，不是画质增强功能，正式演示无需开启。

## 七、超时删减方案

如果第一遍超过 10 分钟，按以下顺序删减：

1. 板级配置不逐个念 I2C/I2S 引脚。
2. POST 信令只说“SDP、ICE 和自定义命令”，不逐个展开。
3. WebRTC 启动不解释数据通道回调。
4. 雷达不讲距离分辨率字段。
5. 视觉不讲自动降帧的具体毫秒数。
6. 网页不讲框颜色和 CSS。
7. 结尾只说“14 项检查全部通过”。

不得删去：官方基线、WT99P4C5-S1 适配、统一来电入口、通话中音频混合、雷达与视觉双证据、非身份识别、当前未实现的四项边界。
