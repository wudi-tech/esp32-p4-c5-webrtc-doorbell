# ESP32-P4+C5 多模态 WebRTC 智能门铃使用指南（ESP-IDF 版）

## 1. 项目简介

本工程以 Espressif `esp-webrtc-solution` 的 `solutions/doorbell_local` 为基础，适配 WT99P4C5-S1，并增加舵机模拟门锁、HLK-LD2450 雷达、摄像头人体存在检测、中文网页和多模态门铃触发。

原项目地址：<https://github.com/espressif/esp-webrtc-solution>

本指南面向 Windows + ESP-IDF 开发环境。电脑和门铃应连接同一个 2.4 GHz 局域网。最终演示使用空载舵机模拟门锁，不连接真实锁体。

## 4. 引脚连接与电源

所有接线和插拔排线必须在断电状态完成。

### 4.1 摄像头、扬声器与主板

- OV5647 排线插入主板 `MIPI_CSI` 接口，确认触点方向后锁紧卡扣。
- 4 Ω 3 W 扬声器插入主板 `SPK` 接口。该接口为功放输出，不要接耳机或线路输入设备。
- 调试时使用带数据功能的 USB-C 线连接主板 USB-UART 口和电脑。

### 4.2 舵机

| 舵机线 | 连接位置 |
| --- | --- |
| 黄色/橙色，PWM | WT99P4C5-S1 J6 pin 20 / ESP32-P4 GPIO32 |
| 红色，+5 V | 降压模块稳压 5 V 输出正极 |
| 棕色/黑色，GND | 降压模块输出负极 |
| 主板 GND | J6 pin 11/13/15/17 任一 GND，与舵机电源共地 |

舵机 PWM 为 50 Hz：500 μs 为锁定位置，2500 μs 为打开位置，打开后保持约 5 秒再复位。不要将舵机红线接到 3.3 V。

### 4.3 HLK-LD2450 雷达

| LD2450 引脚 | 连接位置 |
| --- | --- |
| 5V | 降压模块稳压 5 V 输出正极，使用独立分支 |
| GND | 降压模块输出负极，并与主板共地 |
| TX | J6 pin 10 / ESP32-P4 GPIO4（UART1 RX） |
| RX | J6 pin 12 / ESP32-P4 GPIO5（UART1 TX） |

串口为 256000 baud、8N1。TX 与 RX 必须交叉连接。

### 4.4 电源板连接拓扑

推荐供电方式：

```text
9 V / 2.22 A 适配器
        │
        ▼
三路可调降压模块（先用万用表调至 5.0 V）
        ├── 5 V 分支 A ── 舵机红线
        └── 5 V 分支 B ── LD2450 5V

所有 GND ── 电源板 OUT- ── 主板 J6 GND

电脑 USB-C ── 主板供电与串口
```

注意事项：

- 先空载测量输出为 5.0 V，再连接舵机和雷达。
- 5 V / 3 A 适配器不能通过仅能降压的模块来“保持 5 V”，应绕过该降压级或换用合适的稳压方案。
- 外部 5 V 不要与主板 USB 5 V 直接并联；本方案只把地连接在一起。
- 舵机和雷达使用两个输出分支，降低舵机电流变化对雷达串口的干扰。
- 舵机堵转、异常抖动或明显发热时立即断电。

## 5. 安装并检查 ESP-IDF

使用 Espressif Windows 安装器安装 ESP-IDF v5.5.5，然后从开始菜单打开该版本的 ESP-IDF 命令行。不要在未初始化的普通 PowerShell 或 Anaconda 终端中直接运行 `idf.py`。

检查环境：

```powershell
idf.py --version
python --version
Get-CimInstance Win32_SerialPort | Select-Object DeviceID,Name
```

预期可以看到 ESP-IDF v5.5.5、Python 3.11 和 CP210x 串口。

## 7. 编译与烧录

在工程根目录依次执行：

```powershell
idf.py -C solutions/doorbell_local set-target esp32p4
idf.py -C solutions/doorbell_local reconfigure
idf.py -C solutions/doorbell_local build
idf.py -C solutions/doorbell_local -p COM5 flash monitor
```

换电脑后将 `COM5` 改为实际串口。退出串口监视器使用 `Ctrl+]`。

如果无法自动进入下载模式：按住 BOOT，短按 RST，松开 BOOT，然后重新执行烧录命令。

成功启动后，串口应出现类似信息：

```text
Detected Camera sensor PID=0x5647
Identified slave [esp32c5]
LD2450: UART1 ready at 256000 baud (RX GPIO4, TX GPIO5)
NETWORK: got ip:192.168.x.x
Use browser to enter https://192.168.x.x/webrtc/test for test
Vision models: pedestrian=ready face=ready
```

## 8. 首次上电检查

1. 确认摄像头排线、扬声器插头、舵机 PWM、雷达 TX/RX 和共地连接正确。
2. 先给主板上电，观察串口是否识别 P4、PSRAM、C5、摄像头和音频设备。
3. 再给雷达和舵机电源板上电，确认稳压输出保持在 5 V 附近。
4. 雷达应能输出目标帧，舵机上电后应停在锁定位置，不应持续抖动。
5. 记录串口显示的局域网 IP 地址。

## 9. 项目使用流程

1. 让电脑与门铃连接同一个 2.4 GHz Wi-Fi。
2. 使用 Chrome 或 Edge 打开 `https://设备IP/webrtc/test`。
3. 首次访问时接受本地自签名 HTTPS 证书风险提示。
4. 等待页面显示“已连接到信令服务器”。
5. 按开发板 BOOT，或让融合策略确认门前有人；浏览器进入来电状态并播放铃声。
6. 点击“接听”，通常约 4～6 秒建立视频和双向语音。
7. 使用耳机验证通话：对板载麦克风说话应能从浏览器听到，浏览器麦克风声音应由板载扬声器播放。
8. 点击“开门”，舵机转到打开位置，保持约 5 秒后复位；板端播放开门提示音。
9. 点击“挂断”，等待页面恢复到可呼叫状态。
10. 再按一次 BOOT，确认可再次发起来电。

## 10. 中文网页与传感器信息

- 雷达目标显示 X/Y 坐标、速度、进入/离开和门前区域状态。
- X 表示左右方向，Y 表示雷达正前方距离；坐标单位为毫米。
- “检测事件”是进入、离开和视觉状态变化的有限历史记录，不是当前人数，也不会直接代表某个目标的身份。
- 视频绿色框表示已确认行人，黄色框表示近距离人脸存在辅助结果，灰色框表示尚未连续确认的候选。
- 置信度表示模型认为检测框属于该目标类别的把握程度，不是人脸身份相似度。
- “模型就绪”表示模型已加载；没有检测框不等于模型未启动。
- 本雷达输出二维目标点，不是激光雷达点云，也不能还原人体轮廓。

## 12. 常见问题

### 12.1 找不到 `idf.py`

关闭当前终端，从开始菜单打开 ESP-IDF v5.5.5 命令行，再进入工程目录。CMD 中使用 `%IDF_PATH%`，PowerShell 中使用 `$env:IDF_PATH`，不要混用。

### 12.2 页面打不开

- 确认电脑和门铃在同一子网。
- 以串口最新打印的 IP 为准，Wi-Fi 重连后 IP 可能变化。
- 确认使用 `https://` 而不是 `http://`。

### 12.3 呼叫建立慢或没有视频

- 正常局域网建立时间约 4～6 秒，可先等待 10 秒并观察连接状态。
- 刷新页面后再试，不要同时打开多个测试页面。
- 关闭占用网络的下载任务，保证 2.4 GHz Wi-Fi 信号稳定。

### 12.4 BOOT 没有来电

- 确认页面已经连接到信令服务器。
- 结束上一通通话并等待状态恢复。
- 串口应打印 `BOOT level changed` 和 `BOOT ring request: ACCEPTED`。

### 12.5 摄像头没有检测框或误检

- 让人体尽量完整进入画面，避免过近、逆光、严重遮挡和镜头大幅抖动。
- 在镜头前停留数帧，系统使用连续帧确认，不会把单帧立即判定为人。
- 串口应显示行人和人脸存在模型均为 `ready`。
- 视觉模型只判断目标类别，不能保证在所有光线和角度下 100% 准确。

### 12.6 雷达文字异常或位置不符合预期

- 检查雷达 TX→GPIO4、RX→GPIO5 是否交叉连接。
- 检查 256000 baud 和共地。
- 移动目标应在 X=-1500～1500 mm、Y=300～3000 mm 的门前区域内。
- 金属物体、风扇和区域外运动也可能形成目标点，需结合摄像头判断。

### 12.7 舵机异常抖动、堵转或发热

- 立即断开舵机电源。
- 检查独立 5 V 供电和共地，确认供电没有接到 3.3 V。
- 空载验证 0°→180°→0°动作，再考虑机械安装。
- 当前没有电流和位置反馈，不能用于无人值守的真实门锁。

### 12.8 显示通话结束但视频仍在

刷新页面并只保留一个测试标签页。若反复出现，采集串口日志和浏览器控制台信息，检查挂断确认是否送达。

## 13. 安全与隐私

- 不要在源码、截图或录屏中展示 Wi-Fi 密码、私人聊天、个人证件和家庭隐私区域。
- 本项目使用自签名 HTTPS 证书，仅适用于受信任的本地测试网络。
- 舵机没有位置反馈，连接真实门锁前必须增加机械限位、电流检测或位置检测。
- 调整降压模块时必须先断开负载并使用万用表，避免过压损坏雷达或舵机。
