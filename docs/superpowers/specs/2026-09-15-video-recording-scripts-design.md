# 五分钟项目演示与代码讲解脚本设计

## 1. 目标

为 ESP32-P4+C5 多模态 WebRTC 智能门铃制作两份能够直接照读、照拍的中文录制脚本：

1. 项目使用流程演示脚本，成片不超过 5 分钟。
2. 代码录屏讲解脚本，成片不超过 5 分钟。

两份视频面向项目评审。脚本既要证明作品可以完整运行，也要清楚说明作品基于 Espressif `esp-webrtc-solution/solutions/doorbell_local` 完成复刻，并增加了舵机、毫米波雷达、人体存在检测、中文界面和多模态触发。

## 2. 总体叙事方案

采用“证据驱动型”结构：每项口述都由同步画面或代码证据支撑，不使用只讲概念、不展示结果的段落。

- 项目演示按照“人员出现 → 来电 → 接听 → 音视频 → 开门 → 挂断 → 再次呼叫”的完整闭环组织。
- 代码讲解先展示工程地图，再沿“启动、呼叫、通话、开门、感知融合”五条调用链进入关键文件。
- 不逐行念代码，只解释模块职责、关键配置、调用关系和本项目增加的实现。
- 全程明确空载舵机只是在模拟门锁，视觉功能只判断是否有人，不做人脸身份识别。

## 3. 项目流程演示脚本设计

### 3.1 成片与拍摄方式

- 目标时长约 4 分 30 秒，硬上限 5 分钟。
- 1920×1080 横屏、30 FPS、H.264。
- 电脑录屏作为主画面，手机横屏拍摄硬件，后期放在右下角画中画。
- 关键动作必须同时看到操作和反馈，例如按下 BOOT 时同时看到手部动作和网页来电状态。
- 双向语音使用两句不同的固定台词，防止评审无法分辨声音方向。

### 3.2 时间结构

| 时间 | 内容 | 主要证据 |
| --- | --- | --- |
| 0:00～0:25 | 作品和硬件介绍 | 主板、摄像头、雷达、扬声器、舵机和供电板 |
| 0:25～0:50 | 上电与中文网页 | 页面连接状态、摄像头视频、传感器区域 |
| 0:50～1:25 | 人员进入与检测 | 雷达坐标、摄像头检测框、事件记录 |
| 1:25～1:55 | BOOT 实体按键来电 | 手按 BOOT、网页来电和铃声同步 |
| 1:55～2:50 | 接听与双向音视频 | 4～6 秒接通、远程画面和两个方向的声音 |
| 2:50～3:35 | 通话中模拟开门 | 舵机动作、开门播报、通话不中断、五秒复位 |
| 3:35～4:05 | 挂断与再次来电 | 媒体停止、状态恢复、第二次来电和拒绝 |
| 4:05～4:30 | 总结 | 官方核心功能及本项目增强项 |

### 3.3 脚本字段

最终每个分镜必须包含：准确时间、完整口播台词、电脑录屏画面、手机硬件画面、操作者动作、画面应出现的成功标志、失误后的补拍方式和可删减台词。脚本还应包含录制前布置、音频防回授方法、隐私检查和成片验收表。

## 4. 代码录屏讲解脚本设计

### 4.1 成片与录制方式

- 目标时长约 4 分 50 秒，硬上限 5 分钟。
- 1920×1080 横屏、30 FPS，编辑器字号至少 18 px。
- 录制前按讲解顺序打开代码标签页，使用函数名搜索或预先设置书签，避免现场查找。
- 禁止打开 `settings.local.h`，不得录入真实 Wi-Fi 名称和密码。
- 每一段以“文件职责 → 关键代码 → 调用关系 → 实际效果”的顺序讲解。

### 4.2 时间结构

| 时间 | 代码主题 | 主要文件 |
| --- | --- | --- |
| 0:00～0:25 | 工程地图与源码组成 | `CMakeLists.txt`、目录树 |
| 0:25～0:55 | WT99P4C5-S1 板级配置 | `settings.h`、`board_cfg.txt`、`sdkconfig.defaults.esp32p4` |
| 0:55～1:30 | 应用启动顺序 | `main.c` 的 `app_main()` 和任务调度配置 |
| 1:30～2:15 | WebRTC、信令与门铃状态 | `webrtc.c`、`webrtc_http_server.c` |
| 2:15～2:50 | 舵机与通话中开门播报 | `door_lock.c`、`door_lock_state.c`、`doorbell_audio_render.c`、`pcm_overlay.c` |
| 2:50～3:35 | 雷达解析与融合 | `radar_ld2450.c`、`presence_fusion.c`、`multimodal_fusion.c` |
| 3:35～4:20 | 视觉检测链路 | `pedestrain_detect.cpp`、`pedestrian_filter.c`、`vision_tracker.c`、`vision_event.c` |
| 4:20～4:40 | 中文网页 | `webrtc_test.html` |
| 4:40～4:50 | 自动检查和总结 | `solutions/doorbell_local/tests/verify_*.py` |

### 4.3 脚本字段

最终每一段必须标明：要说的完整台词、打开的文件、定位的函数或常量、建议选中的代码范围、该代码的功能、上游调用者、下游调用对象、画面停留时间和超时删减项。脚本中的行号应以当前提交源码为准，同时保留函数名，防止后续小幅改动导致行号失效。

## 5. 代码结构地图设计

代码结构说明作为代码脚本的附录，按职责分成以下层次：

1. 构建与配置层：`CMakeLists.txt`、`idf_component.yml`、`settings.h`、`sdkconfig.defaults.esp32p4` 和 `components/codec_board/board_cfg.txt`。
2. 应用入口层：`main.c`，负责初始化、任务调度、BOOT 输入和传感器事件汇总。
3. WebRTC 与网络层：`webrtc.c`、`webrtc_http_server.c`、`media_sys.c` 和公共网络代码。
4. 门铃状态层：`doorbell_ring_policy.c`、`doorbell_status.c` 和 `doorbell_event.c`。
5. 音频层：`doorbell_audio_render.c` 与 `pcm_overlay.c`。
6. 舵机层：`door_lock.c` 与 `door_lock_state.c`。
7. 雷达层：`radar_ld2450.c` 与 `presence_fusion.c`。
8. 视觉层：`pedestrain_detect.cpp`、`pedestrian_filter.c`、`camera_motion.c`、`vision_tracker.c`、`vision_event.c` 和 `pedestrian_format_probe.c`。
9. 多模态融合层：`multimodal_fusion.c`。
10. 浏览器界面层：`webrtc_test.html`。
11. 自动检查层：`solutions/doorbell_local/tests/verify_*.py` 及配套 C 测试。

附录还应给出五条调用链：系统启动链、BOOT 来电链、浏览器接听与挂断链、通话中开门链、雷达/视觉融合来电链。

## 7. 验收标准

- 两份脚本的总时长均不超过 5 分钟。
- 项目演示脚本包含全部台词与逐镜头画面说明。
- 代码讲解脚本包含全部台词、准确文件、函数、当前行号、功能和调用关系。
- 代码结构附录覆盖所有核心模块和五条主调用链。
- 脚本没有模板占位符、真实 Wi-Fi 信息或不符合当前实现的功能描述。
- 文件同步后，源码、最终提交目录和 ZIP 中的脚本内容一致。
